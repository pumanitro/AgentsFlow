Peers Flow · how it works

How a routine rings your bell

I ran your "Abilitie timesheet" routine just now. About a minute and a half later the bell in Peers Flow showed an orange 1 with the timesheet waiting for you. Here is what happened in between, and what you do and don't have to set up.

Short answer: there's nothing to set up. Every chat that Peers Flow starts, including routine runs, gets Peers Flow's own built-in tool kit ("peersflow"). That kit now contains a notify tool. The agent calls it, the tool talks straight to the app, and the app shows the bell. Routines also raise a warning by themselves when a run fails or is missed, without any agent involved.

Two ways a routine reaches the bell

📣 The agent asks

The routine's agent calls notify when it needs you: files to check, questions, to-dos. That's the timesheet case.

⚠️ The run goes wrong

If a run fails or is missed (e.g. the Mac was off), Peers Flow raises a warning by itself, with no agent involved. Marking the run done clears it.

🤫 Nothing needed

A run that just finishes makes no notice. You asked to drop the "just so you know" kind.

Technical details: the actual plumbing

The config Peers Flow wrote for this routine's chat (it's what plugs in the tool kit):

{"mcpServers": {"peersflow": {
  "command": ".../Electron (as node)",
  "args": [".../dist/electron/electron/mcp/agentsflow-mcp-server.js"],
  "env": {
    "PEERSFLOW_BRIDGE_SOCK": "~/Library/Application Support/Peers Flow/peersflow-bridge.sock",
    "PEERSFLOW_ROOT_CONVERSATION_ID": "b2308b29-…",   ← this routine's chat
    "PEERSFLOW_ROOT_DIR": "/Users/iij/Desktop/LISA"
}}}}

Chain: agent → notify (MCP tool) → MCP server → bridge socket peersflow-bridge.sock → Electron main → notifications.json → IPC push → bell + drawer. Answers: drawer → main → message into the source chat (open terminal, background attach, or a background resume if the chat ended). Automatic warnings: the routine scheduler's run-ended hook raises a warn on failed/missed.
